# 模块报告规范

每完成一个**功能切片**，在 `backend/docs/progress/` 写一份报告，并在 `_index.md` 加一行索引。

## 文件命名
`YYYYMMDD-<模块>-<简述>.md`，如 `20260601-auth-register.md`。

## 报告模板（中文）
```markdown
# <切片名称>

- 日期：YYYY-MM-DD
- 分支：feat/xxx
- 对应契约：apiDesigner.md 的 X.X（如有）
- 状态：完成 / 部分完成（说明）

## 做了什么
- 新增/修改了哪些文件（列路径）
- 实现了哪些接口/功能

## 怎么做的（便于排错——重点！）
- 关键实现思路、用了哪些技术点（如 JWT 过滤器、AOP 日志切面、MyBatis-Plus 分页插件）
- 数据流：请求 → Controller → Service → Mapper → DB 的关键步骤
- 有 Flyway 迁移就写明版本号与做了什么

## 关键决策与假设
- 做了哪些设计取舍
- 契约/架构没写清、我自行假设的地方（**重大假设应在动手前就问**，不该出现在这里）

## 测试
- 关键路径测了什么、怎么测、结果

## 与架构/契约的偏差
- 有无不一致；为什么

## 遗留 / 待批准
- 未完成项、阻塞项（同时应记入 pending-approval.md）

## 下一步
- 建议的下一个切片
```

**Why:** 用户远程、不在现场看你敲键盘；报告（尤其"怎么做的"）是他理解与排错的唯一窗口。
**How to apply:** 切片一完成就写，宁可啰嗦也要让人能照着复现和排错；写完去 `_index.md` 补一行。
