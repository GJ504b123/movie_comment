## 怎么做的

### 认证流程

```
注册：POST /api/auth/register
  → AuthController → UserService.register()
  → 检查 username 唯一（重复→409）
  → BCrypt 加密密码
  → 插入 user（role=user, status=pending）
  → 返回 {userId, status:"pending"}

登录：POST /api/auth/login
  → 查 username → 不存在→401
  → BCrypt 比对密码 → 不匹配→401
  → 检查 status：pending→403 "等待审核" / rejected→403 "审核未通过"
  → JwtUtils.generate(userId, username, role) → 生成 token
  → 更新 lastLoginTime
  → 返回 {token, user:{id,username,email,role,status}}

后续请求：
  → JwtAuthFilter 拦截 → 解析 Authorization 头 → 验证 JWT → 设 UserContext
  → Controller 通过 UserContext.getUserId() 获取当前用户
  → 无 token 访问需认证接口 → 401 "未提供认证凭证"
```

### JWT 设计
- **签名算法**：HMAC-SHA256
- **载荷内容**：`sub`=userId、`username`、`role`
- **过期**：默认 120 分钟，可通过 `JWT_EXPIRE_MINUTES` 环境变量调整
- **密钥**：从 `JWT_SECRET` 环境变量读取，至少 32 字节

### 鉴权方案（轻量自写）
- 未使用 Spring Security 完整过滤链
- `JwtAuthFilter` 是 `OncePerRequestFilter`，Spring Boot 自动注册
- 公开路径：`/api/auth/**`、Swagger UI、API docs——不强制 token
- 游客可访问：影片列表/详情/排行榜——过滤器不放行也不报错，Controller 自己判断是否需要登录
- 需登录：`/api/user/**`、评论相关、管理员接口——Controller 调 `requireLogin()` 抛 401

### 状态校验
- 注册 → `status=pending`
- 登录 → 检查 status：只有 `approved` 能登录
- `pending` → 403 "用户尚未通过审核"
- `rejected` → 403 "审核未通过"

## 关键决策与假设
- 过滤器不区分"无 token"和"token 无效"——两者都放行到 Controller，由业务方法决定是否拒绝。这比全局拦截更灵活（支持部分接口游客可访问）
- 密码修改要求旧密码验证（`oldPassword` 必填且正确）
- 所有时间字段返回 ISO 8601 字符串
